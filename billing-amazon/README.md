# Amazon purchasing integration seam

This Android library compiles against Amazon Appstore SDK 3.0.9. It is deliberately **not a dependency of the offline app**. The separate Amazon variants now use it with parent purchase/restore controls and starter/Family enforcement; see `../docs/AMAZON-INTEGRATION.md`. There are no configured live products, invented prices or trials.

The adapter retrieves store product data, starts only parent-authorised requests, pages purchase updates, restores, receives cancellations, calls a server receipt verifier, and caches ECDSA-signed access with bounded offline validity. `HttpsReceiptVerifier` connects to the publisher endpoint implemented in `billing-service`; both remain disconnected from the offline app. Tokens bind environment, user, SKU and receipt. Expired, tampered, wrong-account or sandbox tokens cannot grant production access. New verification can shorten a receipt's lease; stale responses and callbacks for a switched Amazon account are rejected. An authoritative inactive-receipt response clears matching cached access. No Amazon shared secret belongs in an APK.

Before integrating: obtain `AppstoreAuthenticationKey.pem` from the actual developer app and use actual store SKUs; pin the receipt service's signing public key with separate sandbox/production keys; deploy the HTTPS verifier with protected secrets and rate limits; validate the implemented parent-only price/restore UI and free/premium feature limits with live store data; update the privacy notice for account/receipt processing; and test the actual SDK with Amazon App Tester and a physical Fire tablet. Local cache/HTTP configuration tests deliberately omit the SDK receiver because its obfuscated Android bytecode cannot be validated as a desktop JVM broadcast receiver. These tests do not claim live purchase or restore success. A network failure during restore preserves otherwise valid cached access only until its signed refresh deadline.

Official sources checked 20 October 2026: [SDK integration](https://developer.amazon.com/docs/appstore-sdk/integrate-appstore-sdk.html), [IAP implementation](https://developer.amazon.com/docs/in-app-purchasing/iap-implement-iap.html). This seam is not an assertion that live store integration has passed.

The catalog now explicitly maps buyable term SKUs to receipt parent SKUs, querying both while showing only buyable priced products. See AmazonProductCatalog and its tests. The former single skus setting is replaced by productMappings; old/incomplete configuration fails closed.
