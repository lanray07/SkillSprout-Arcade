# Localisation workflow

The app packages 19 interface variants: en-GB, en-US, fr, es, de, it, pt-BR, pt-PT, nl, pl, ar, hi, ja, ko, zh-Hans, zh-Hant, tr, id and sv. It detects the device language, provides an explicit parent-only language selector and falls back to UK English. Changing language relocks the parent area. Learning activities and their narration remain English; translated interface resources do not imply translated educational packs.

The 18 additional catalogues cover all 338 current source entries, including plural entries. Most were generated locally with Argos/CTranslate2 models, then corrected by assistant editorial overrides. Traditional Chinese uses OpenCC conversion plus editorial corrections. US English is a source baseline. No paid translation service or translation model runs inside the app. See `translation-requirements.txt` under tools for optional development dependencies; model archives and the Python runtime remain ignored build artifacts.

`python tools/check_interface_languages.py` checks the actual compiled-resource inputs: source and target hashes, complete key sets, placeholders, required plural forms, selector consistency and pathological model repetition. It does not establish naturalness or educational suitability. Arabic has six plural quantities, Polish has four, and English learning prompts, meaningful tile order and diagrams keep left-to-right layout within the Arabic interface. Narration obtains English strings explicitly.

Each `.machine.json` records provenance and model attribution. Raw `.pending.json` outputs are preserved for traceability; the app uses the corrected XML listed in `packaged-interface-locales.json`. Review actual packaged resources, not only raw model outputs. Source-bound corrections are in `editorial-ui-overrides.json` and `plural-ui-overrides.json`. Changes to English source invalidate earlier hashes.

The publisher explicitly waived independent language review. `python tools/package_interface_languages.py --publisher-waived-language-review` is the separate packaging path for that instruction. It records the waiver and never creates human-review or production approvals. The original `tools/localise.py export --locale ...` path still requires a genuine source-bound reviewer record. Machine output, automated checks and assistant corrections must never be labelled native-speaker approval.

The bundled full privacy policy is English, with a translated interface summary. Store screenshots and metadata need separate final-candidate reconciliation. UI resource coverage does not establish complete translated website/store content, audible multilingual accessibility or complete layout coverage. Physical resource-selection checks and Compose UI tests are recorded separately with their actual scope.
